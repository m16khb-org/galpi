- 기준 커밋: `63be366` (main)
- 갱신 필요: 이 문서의 1장 "현재 상태"는 WhisperX 기본·`~/Downloads/whisperx-out` 시절
  기준이다. 현재 기본 전사 엔진은 Qwen3이고 산출물은 사용자가 고른 폴더에 저장된다.

## 1. 현재 상태 (As-Is)

### 1.1 완성된 기능

| 영역 | 내용 |
|---|---|
| 녹음 | CoreAudio 마이크 → bounded queue → WAV writer. `.wav.part` 원자적 완료, 버리기 지원 |
| 전사 | WhisperX `large-v3-turbo` 한국어 ASR(CTranslate2 CPU int8) + 문장 정렬 + pyannote 화자분리(MPS, CPU 폴백) |
| 입력 | 마이크 녹음 및 `m4a`/`mp3`/`wav`/`mp4`/`mov`/`aac`/`flac`/`ogg` 파일 가져오기 |
| 품질 | 화자 수 힌트(자동/정확히/범위), 장기 무음 환각 필터링, 체크포인트 재사용(`.aligned.v2.json`) |
| 산출물 | `.srt`, `_화자별.txt`, `.aligned.v2.json` — 작업별 독립 디렉터리 |
| 회의록(assistant) | z.ai `glm-5.3`로 전사본을 한국어 회의록 Markdown으로 정제. 설정(API 키/모델/사전 정보) 저장, 작업 취소·감독 포함 |
| 셋업 | 번들 `uv` + 앱 전용 Python 3.12 + 모델 자동 준비, HF 토큰 설정(`0600` settings.json) |
| 배포 | `hdiutil` DMG(미서명·미공증) |

### 1.2 아키텍처 확장 포인트

- IPC 명령 13개: 환경 진단/준비 2, 토큰 2, assistant 설정 2, 회의록 정제 1, 전사 2(시작/취소), 산출물 2(열기/Finder), 녹음 3.
- 포트 구조: `DesktopAdapter`(엔진/전사/산출물) + `RefinementJob` 회의록 포트 + `NativeRecorder`. 모든 외부 효과는 `composition.rs`에서만 구체 배선.
- 워커 프로토콜은 버전이 지정된 JSONL. 회의록 정제는 `galpi_worker refine` 서브커맨드로 이미 분리되어 있어 **전사 파이프라인과 독립적으로 진화 가능**.
- 프론트엔드는 순수 상태머신(`src/application/*-machine.ts`) + Zod 경계 파싱 + DOM 뷰 분리.

### 1.3 현재의 빈틈

1. **결과가 파일로만 존재한다.** 작업이 끝나면 화면 상태가 사라지고, 사용자는 `~/Downloads/whisperx-out`을 Finder로 뒤져야 한다. "그때 그 회의"를 다시 찾는 방법이 앱 안에 없다.
2. **회의록이 한 번 만들어지면 끝이다.** 화자 이름(`SPEAKER_00`)이나 용어를 알게 된 뒤 사전 정보를 고쳐서 다시 만들 수 있지만, 화자-이름 매핑이 어디에도 저장되지 않는다. 매번 처음부터 다시 쓴다.
3. **온라인 회의를 못 녹음한다.** 마이크 입력만 캡처하므로 Zoom/Meet 상대방의 발언이 빠진다(README에 명시된 제약).
4. **배포가 열려 있다.** 서명/공증/자동 업데이트가 없어 다른 Mac에 안심하고 설치시키기 어렵다.

## 2. 제품 방향과 다음 스텝 선정

### 2.1 제품 테제

> 갈피는 "회의가 끝난 뒤 남는 것"을 로컬에서 완성한다. 녹음 한 번으로 결정·담당·기한이 정리된 회의록까지 나오고, 그 기록이 쌓여 다음 회의의 갈피가 된다.

전사→회의록 파이프라인(v0.1)이 "한 번의 회의"를 끝냈다면, 다음은 "회의가 쌓이는 경험"을 만들 차례다.

### 2.2 선정 기준

- (a) 방금 착지한 회의록 기능의 가치를 즉시 복리로 만드는가
- (b) 로컬 우선 원칙(음성·텍스트는 사용자 폴더에만)을 깨지 않는가
- (c) 기존 아키텍처(포트/어댑터, 단일 작업 레지스트리) 안에서 자연스러운가
- (d) 워커 프로토콜 변경 없이 가능한가

### 2.3 후보 비교

| 후보 | 가치 | 노력 | (a)~(d) | 판정 |
|---|---|---|---|---|
| **회의 라이브러리 + 회의록 완성 루프** | 높음 — 모든 후속 기능의 기반 | 중 | 모두 충족 | **v0.2 선정** |
| 시스템 오디오 캡처(SCStream) | 높음 — 온라인 회의 필수 | 높음 — 네이티브 대형 작업, 권한·프레임워크 리스크 | (a) 무관 | v0.3 |
| 화자 보이스프린트(목소리로 자동 실명) | 높음 | 높음 — 모델 선정·데이터 축적 필요, 라이브러리가 선행되어야 저장·재사용 가능 | 라이브러리 의존 | v0.4 |
| 실시간 전사 | 높음 | 매우 높음 — 파이프라인 재설계 | (c)(d) 위반 | 나중 |
| 서명/공증/자동 업데이트 | 중 — 운영 신뢰성 | 낮음~중 | 제약 없음 | v0.2~v0.3 병행 트랙 |

### 2.4 선정 요약

**v0.2 = "회의 라이브러리와 회의록 완성 루프"**

- 회의를 앱 안의 1급 객체로 만든다(목록·상세·재열람).
- 화자 이름과 사전 정보를 회의 단위로 저장하고, 회의록을 몇 번이든 다시 만들 수 있게 한다.
- 워커 프로토콜, 전사 파이프라인, 배포 대상은 그대로 둔다.

## 3. v0.2 상세 설계 — 회의 라이브러리와 회의록 완성 루프

### 3.1 목표 / 비목표

**목표**

1. 앱을 껐다 켜도 지금까지의 회의가 목록에 보이고, 상세에서 전사본·회의록·산출물을 다시 열 수 있다.
2. 회의별로 화자 이름(`SPEAKER_00` → 실명/별칭)을 저장하고, 이 값이 회의록 재생성의 사전 정보에 자동으로 반영된다.
3. 회의록을 앱 안에서 읽고, 필요하면 원문을 편집해 저장할 수 있다.
4. (선택) 전사 완료 후 회의록을 자동으로 이어서 만드는 원패스 옵션을 제공한다.

**비목표 (v0.2 범위 밖)**

- 시스템 오디오 캡처, 실시간 전사, 클라우드 동기화/공유/협업
- 전사 결과 자체의 인앱 편집(타임라인 수정)
- 보이스프린트 기반 자동 화자 식별
- 검색·통계(라이브러리 기반이 잡힌 뒤 v0.4에서)

### 3.2 사용자 여정

```
[녹음/파일 전사 완료]
   └─ 완료 화면에서 "회의록 만들기"(기존) 또는 자동 원패스(F5)
        └─ 회의록 생성 완료 → 회의는 라이브러리에 기록됨
[나중에 앱 실행]
   └─ 라이브러리에서 회의 선택
        ├─ 상세: 메타정보, 산출물 열기, 전사본 보기
        ├─ 화자 이름 지정/수정 → 저장(F4)
        ├─ "회의록 다시 만들기" → 저장된 화자 이름이 사전 정보에 주입됨(F4)
        └─ 회의록 보기/편집/저장(F3)
```

### 3.3 기능 명세

#### F1. 작업 기록 인덱스와 라이브러리 목록

- 전사/회의록 작업 완료 시 작업 디렉터리에 `galpi-meeting.json`(매니페스트)을 원자적으로 기록한다.
- 라이브러리 화면은 출력 루트 하위의 작업 디렉터리를 스캔해 매니페스트를 읽는다(요청 시 재스캔, 백그라운드 감시 없음).
- 목록 항목: 제목(오디오 파일명), 날짜, 길이, 화자 수, 회의록 유무(상태 라벨), 산출물 경로 존재 여부.
- 매니페스트가 없는 레거시 디렉터리(v0.1 출력)는 `.aligned.v2.json`/`.srt` 존재 여부로 최소 정보를 복원해 **읽기 전용**으로 표시한다. "이 회의를 라이브러리에 등록" 동작으로 매니페스트를 생성할 수 있다.
- 디렉터리가 이동/삭제된 회의는 "위치 없음" 상태로 표시하고, 폴더 재지정으로 다시 연결할 수 있다.

#### F2. 회의 상세 보기

- 메타정보(제목 편집 가능, 날짜, 길이, 화자 수, 입력 파일, 출력 경로)와 산출물 목록(SRT/화자별 텍스트/정렬 JSON/회의록)을 보여준다.
- 산출물 열기는 기존 `open_artifact` / `reveal_output_directory` 명령을 재사용한다.
- `_화자별.txt`를 앱 안에서 읽기 전용 타임라인으로 표시한다(외부 파일 규칙 유지, 파일 자체는 수정하지 않음).

#### F3. 회의록 뷰어와 편집

- 생성된 회의록 Markdown을 앱 안에서 렌더해 보여준다.
- "편집" 전환 시 원문 Markdown을 편집할 수 있고, 저장은 임시 파일→원자적 교체(`Path.replace`)로 워커의 `write_text_atomic`과 같은 규칙을 따른다.
- 회의록이 없는 회의는 "회의록 만들기"로 기존 `refine_transcript` 경로를 그대로 호출한다.

#### F4. 화자 이름 지정과 회의록 완성 루프 (핵심)

- 회의 상세에서 화자 라벨별로 이름/별칭을 입력해 저장한다. 매니페스트의 `speakers` 맵에 보관한다.
- "회의록 다시 만들기"를 누르면 저장된 화자 이름과 기존 사전 정보(전역 배경 노트)를 합성해 `refine_transcript`의 `background`로 넘긴다. 형식 예:

  ```
  [화자]
  - SPEAKER_00: 김갈피
  - SPEAKER_01: 이하나
  ```

- 재생성은 기존 단일 작업 레지스트리(`JobRegistry`)와 취소 경로를 그대로 통과하므로 동시성 규칙이 새로 생기지 않는다.
- 회의록 프롬프트(`worker/galpi_worker/minutes_template.py`의 `SYSTEM_PROMPT`)는 이미 `{이름} 추정`과 보정 기록 규칙을 갖고 있어, 화자 이름이 주어지면 근거 있는 실명 치환으로 자연스럽게 수렴한다. **프롬프트 변경은 v0.2에서 최소화한다.**

#### F5. 원패스 옵션 (선택, 마지막에)

- assistant 설정에 "전사가 끝나면 회의록 자동으로 만들기" 토글을 추가한다.
- 전사 완료 이벤트 수신 후 기존 회의록 액션과 같은 경로를 자동 호출한다. 실패해도 전사 결과는 그대로 두고 회의록은 수동 재시도 가능해야 한다.

### 3.4 데이터 모델

**작업 매니페스트** — 각 작업 디렉터리에 1개, 산출물과 함께 살아 있는 단일 진실 원천(앱 데이터가 아니라 사용자 출력 폴더에 존재 → 백업·이동이 출력 폴더 복사로 끝남).

```jsonc
// <출력 폴더>/<파일명>-<작업 ID>/galpi-meeting.json
{
  "version": 1,
  "id": "uuid",
  "createdAt": "2026-08-19T09:41:00+09:00",
  "title": "주간 제품 회의",            // 기본값 = 오디오 파일명, 사용자 편집 가능
  "audioFile": "주간 제품 회의.wav",
  "durationSeconds": 3812,
  "speakerCount": 3,
  "speakers": { "SPEAKER_00": "김갈피" },  // 라벨 → 이름, 비어 있으면 키 없음
  "artifacts": {
    "transcript": "주간 제품 회의_화자별.txt",
    "srt": "주간 제품 회의.srt",
    "aligned": "주간 제품 회의.aligned.v2.json",
    "minutes": "주간 제품 회의_회의록.md"
  },
  "assistant": { "model": "glm-5.3", "generatedAt": "...", "regeneratedCount": 2 }
}
```

- 쓰기 규칙: 형제 임시 파일 + `Path.replace` 원자적 교체, UTF-8. 워커가 아니라 **Rust 호스트가** 기록한다(워커 프로토콜 무변경의 핵심).
- 기존 산출물 파일명(`.aligned.v2.json`, `.srt`, `_화자별.txt`)은 절대 바꾸지 않는다. 회의록 파일명은 `refine_transcript`가 이미 정하는 경로를 따른다.
- 라이브러리 목록 = 출력 루트 스캔 결과. 별도 중앙 인덱스(DB)는 v0.2에서 만들지 않는다. 스캔 비용은 디렉터리 수백 개 수준에서 1회 스캔 수백 ms 이내를 가정하고, 초과하면 상한+안내로 대응한다.
- `durationSeconds`는 기존 산출물에서 유추 가능하면 채우고, 아니면 null(선택 필드)로 둔다.

### 3.5 아키텍처 변경점

**Rust (domain → application → adapters → composition)**

| 계층 | 변경 |
|---|---|
| `domain/` | `MeetingRecord` 순수 모델 + 매니페스트 직렬화/역직렬화 |
| `application/ports.rs` | `LibraryPort` 신설: `list_meetings(root)`, `load_meeting(dir)`, `save_manifest(record)`, `read_minutes(path)` |
| `application/use_cases.rs` | `Application`에 라이브러리 유스케이스 추가. 전사/회의록 완료 경로에서 매니페스트 기록 훅 호출 |
| `adapters/outbound/library.rs` | 파일시스템 구현: 스캔, 원자적 매니페스트 쓰기, 레거시 복원, 경로 포함 검증(canonicalize 후 출력 루트 하위 확인 — 기존 containment 규칙 동일 적용) |
| `adapters/inbound/tauri.rs` | 신규 IPC 명령: `list_meetings`, `load_meeting`, `save_meeting`(제목/화자 이름), `read_meeting_minutes`, `save_meeting_minutes`. `composition.rs`에 핸들러 등록 |

기존 명령은 시그니처 변경 없이 재사용: `refine_transcript`(재생성), `open_artifact`, `reveal_output_directory`, `cancel_job`.

**워커(Python)** — 변경 없음. `refine` 서브커맨드에 화자 이름은 `background` 문자열 합성으로 전달된다. 프로토콜(`worker.rs` + `protocol.py` + Zod 스키마 + 잡 리듀서)은 이번 마일스톤에서 건드리지 않는다(명시적 비목표).

**프론트엔드(TS)**

| 위치 | 변경 |
|---|---|
| `src/domain/job.ts` 확장 또는 `src/domain/meeting.ts` | `MeetingSummary`/`MeetingDetail` 계약 + Zod 스키마 |
| `src/application/library-machine.ts` | 순수 상태머신(로딩/준비됨/빈 상태/오류/재연결 필요). 테스트 동반 |
| `src/adapters/tauri-backend.ts` | 신규 IPC 래핑 + Zod 경계 파싱 |
| `src/ui/` | 라이브러리 목록·상세 화면(템플릿/뷰/컨트롤러 확장). 이벤트 구독 후 호출 순서 준수 |

**의존성 추가: 없음.** (SQLite 등 새 크레이트 불필요 — 파일 매니페스트 방식 채택의 근거)

### 3.6 UI 설계 (DESIGN.md 정합)

- 새 화면 2개: 라이브러리 목록(표: 제목·날짜·길이·화자 수·회의록 상태), 회의 상세(메타 + 산출물 + 화자 이름 편집 + 회의록 뷰어).
- 셸 구조 유지: 설정 레일의 "작업 기록" 진입 또는 작업 영역 상단 탭 전환(열린 결정 사항 Q3). 아래 960px에서 단일 컬럼으로 스택.
- 재사용 컴포넌트: Status Button(회의록 만들기/다시 만들기), Field Group(화자 이름 입력), Phase Timeline(재생성 진행).
- 신규 컴포넌트 2종을 DESIGN.md에 추가하고 `app-template.ts`/`styles.css`와 함께 갱신: **Library Table**(행 상태: ready/minutes-missing/location-lost/read-only-legacy, 상태는 항상 색+텍스트), **Document Viewer**(Markdown 렌더, 편집 전환, 저장 상태 라벨).
- 회의록 Markdown 렌더는 앱에 이미 HTML 파이프라인이 없으므로 최소 자체 렌더러(제한된 요소: 제목/목록/강조/표 없음)를 쓰고, 외부 Markdown 라이브러리 추가는 금지(로컬 우선·공격면 최소화). 프롬프트 산출 구조가 제한적이므로 충분하다.
- 모든 상태 전이는 `aria-live`로 알리고, reduced motion에서 동작 없음.

### 3.7 보안·프라이버시

- 화자 실명·별칭은 사용자 출력 폴더의 매니페스트에만 저장된다(음성·전사본과 같은 위치, 같은 보호 수준). 클라우드 전송 없음.
- 회의록 재생성 시 외부로 나가는 것은 기존과 동일하게 전사본+사전 정보뿐이며, API 키 취급 규칙(`0600` settings.json, 워커 환경변수 주입)은 그대로다.
- 매니페스트 경로는 canonicalize + 출력 루트 containment 검증 후에만 읽고 쓴다(기존 산출물 검증 규칙과 동일).

### 3.8 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 사용자가 출력 폴더를 Finder에서 이동/삭제 | 회의 "위치 없음" | 상태 라벨 + 폴더 재지정으로 재연결. 매니페스트가 디렉터리 안에 있어 이동 후에도 자체 완결 |
| 외부 편집으로 산출물/회의록이 바뀜 | 뷰어 내용 낡음 | 상세 화면 진입 시마다 재로드. 편집 충돌 시 저장 전 덮어쓰기 확인 |
| 대량 디렉터리 스캔 지연 | 목록 느림 | 스캔 상한(예: 500디렉터리) + 초과 시 안내. 필요 시 v0.4에서 인덱스 캐시 |
| 회의록 재생성 실패/취소 반복 | 좌절 | 기존 회의록 파일을 덮지 않고 새로 쓰기 전까지 유지. 실패 시 이전 회의록 그대로 |
| 매니페스트 손상(부분 쓰기) | 회의 인식 실패 | 원자적 교체로 원본 보존. 파싱 실패 행은 "손상" 상태로 표시하고 건너뜀 |
| 프롬프트가 화자 이름을 과신 | 회의록 왜곡 | 프롬프트 규칙 유지(근거 없으면 추정 표기). 화자 이름은 "사용자 확정"이므로 실명 치환 허용이 의도된 동작 |

### 3.9 수용 기준

- 앱 재시작 후 이전 전사 작업이 라이브러리에 표시되고, 상세에서 산출물을 열 수 있다.
- 매니페스트 없는 v0.1 출력 디렉터리가 읽기 전용 항목으로 표시되고, 등록 동작으로 매니페스트가 생긴다.
- 화자 이름을 저장한 뒤 회의록을 다시 만들면 사전 정보에 화자 이름이 포함되고, 완성된 회의록의 화자 보정 기록이 이를 반영한다.
- 회의록 편집 저장이 원자적으로 이뤄지고, 앱 재시작 후에도 유지된다.
- 재생성 중 취소가 기존 취소 UX와 동일하게 동작하고, 이전 회의록 파일은 보존된다.
- 전체 검증 게이트 통과: `bun run check`, `bun test`, `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test --all-targets`, `uvx ruff check/format --check worker`, `basedpyright`, `python -m unittest worker.tests.test_core`(워커 무변경이므로 그대로 녹색).
