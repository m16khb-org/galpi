# 네이티브 런타임 연결 실패는 이제 로그인 화면에 표시되고, 브라우저 QA는 IPC를 가짜로 주입해 확인한다

- Date: 2026-10-09
- Kind: `caution`
- Source: issueops-docs io-21fd3b1e1f06 (issue #10); src/ui/controller.ts, src/ui/access-screen.ts, src/ui/controller.test.ts
- Summary: Google 로그인 필수화 뒤 controller.start()는 이벤트 구독이 실패하면 #app-error 배너 대신 로그인 화면(#access-status)에 재실행 안내를 띄우고 로그인·다시 확인 버튼을 숨긴다. 평범한 브라우저에서는 셸이 inert라 작업 화면을 볼 수 없으므로, 화면 확인은 window.__TAURI_INTERNALS__(invoke·transformCallback)와 __TAURI_EVENT_PLUGIN_INTERNALS__를 init script로 가짜로 넣어 진행한다.
- Context: 2026-08-23 caution은 런타임 연결 실패를 앱 배너로 알린다고 적었다. galpi#10에서 셸은 로그인 전 inert이므로 배너가 보이지 않는다. 또한 app-template에 inert를 정적으로 넣으면 템플릿만 쓰는 happy-dom 테스트(token-guide 포커스 복귀, token-settings)가 포커스를 잃거나 멈춘다.
- Resolution: inert는 AccessScreenView.render가 toggleAttribute로만 건다. 런타임 실패 경로는 controller.test.ts가 로그인 화면 문구·숨은 버튼·signInToGateway 0회로 고정한다. 화면 QA는 Vite 개발 서버 + 가짜 __TAURI_INTERNALS__로 로그인 전·대기·오프라인·로그아웃을 확인했다.
