## Windows 실제 장치 확인 (일회성 코드, 커밋하지 않음)

USB 마이크와 S/PDIF 스피커가 있는 PC에서 `NativeRecorder` 경로를 직접 호출했다. 앱 화면과 설치본은 거치지 않았다.

- 시스템 트랙만 10.05초 동안 녹음하고 중간 3~7초에 440 Hz 톤을 재생했다. 파일 길이는 10.00초이고 앞뒤 무음 구간이 그대로 남았다(1초 창 RMS `95 52 32 9719 11584 11584 11584 6304 103 0`). 무음 출력 스트림 없이 같은 실험을 해 보지는 않았으므로, 그 스트림이 꼭 필요하다는 계획의 가정은 대조하지 않았다.
- `마이크 + 회의 소리` 합친 파일은 10.02초, mono, 48 kHz이며 톤 구간이 들어 있다. 정지부터 합치기 끝까지 0.28초가 걸렸다. 정지 뒤 폴더에는 `<이름>.wav` 하나만 남았다.
- 같은 소스로 녹음하다 버리면 회의 폴더가 남지 않았다. `마이크만` 녹음은 2채널 파일 하나로 이전과 같았다.
- 마이크로는 주변 소음만 들어갔다. 사람이 말하는 소리와 설치한 앱에서의 녹음은 이 환경에서 확인하지 않았다.
- 한국어 음성 합성(Windows `Microsoft Heami`) 26초 분량을 시스템 소리로 재생하며 `마이크 + 회의 소리`로 녹음했다(30.94초, mono, 48 kHz). 이 합친 파일을 설치된 worker(`galpi_worker transcribe --engine whisperx`, CUDA)로 전사하니 `completed`(구간 1개)로 끝났다. 원본 음성 파일을 같은 방식으로 전사한 결과와 낱말이 거의 같고(예: `…칠빌, …, 족발, 뱀수권…`), 시작 시각만 녹음 중 재생을 시작한 만큼 밀려 있다. 두 결과 모두 합성 음성이라 문장 인식은 부정확하다. 이 실험은 합친 파일이 전사 파이프라인을 끝까지 통과하고 시스템 소리가 합치기에서 살아남는다는 증거이며, 인식 정확도의 증거는 아니다. 전사 결과 파일은 보관하지 않았다.

## 합치기 성능 (release, 일회성 측정 코드)

10분 길이 합성 트랙(마이크 48 kHz mono, 시스템 48 kHz 또는 44.1 kHz mono)을 합치는 데 1.16~1.17초가 걸렸다. 60분으로 선형 외삽하면 약 7초다.

## 부작용 목록

- 설정 파일에 `recordingSource` 키가 생긴다. 구버전은 이 키를 무시한다.
- Tauri 명령이 38개에서 40개로 늘었고 `start_recording`에 `source` 인자가 생겼다.
- Windows는 녹음하는 동안 기본 출력 장치에 무음 출력 스트림을 연다.
- 합치는 동안 회의 폴더에 중간 파일 두 개와 합친 `.part`가 함께 있다가 정지가 끝나면 최종 `.wav`만 남는다.
- macOS는 처음 시스템 소리를 녹음할 때 OS 권한 창이 뜰 수 있다.

## UI 판단

- 기존 디자인 시스템: 새 컴포넌트를 만들지 않고 엔진 선택에 쓰는 `segmented-control` 마크업과 SEED `--seed-*` 토큰만 쓴다. 새 색·px 값은 없고, 두 칸 배치를 위한 `.recording-source-segmented`(`grid-template-columns: repeat(2, 1fr)`)와 안내 문단 스타일만 추가했다. SEED action-button 레시피는 쓰지 않는다(버튼이 아니다).
- 접근성: 라디오 그룹은 `role="radiogroup"`과 `aria-label="녹음 소스"`를 가진다. 안내 문단은 `<p>`이고, 보일 때만 그룹의 `aria-describedby`로 연결한다(숨은 문단이 낭독되지 않게 한다). 키보드 조작은 기본 라디오를 따르고 포커스 링은 기존 `.segmented-control input:focus-visible + span` 규칙을 그대로 받는다. 비활성 상태는 기존 규칙(투명도 + `not-allowed`)이며 상태는 색만으로 알리지 않는다: 녹음 중에는 라디오가 `disabled`이고 화면에도 `녹음 중`·`저장 중` 문구가 있다. 선택이 저장되지 않으면 이전 값으로 되돌리고 `#app-error`에 사유를 알린다.
- 반응형: 두 칸 균등 분할이라 최소 폭 920px에서 `마이크 + 회의 소리`가 한 줄에 들어갈 것으로 예상하지만 화면에서 확인하지 않았다.
- 모션: 추가한 애니메이션과 전환이 없어 모션 감소 설정에서 달라질 것이 없다.
- 실제 화면 확인: Not Run. WSL에 Chromium이 없어 브라우저 도구가 열리지 않았고, Windows Edge는 WSL에서 CDP로 붙지 못했다. 대신 happy-dom DOM 테스트가 라디오 선택, 안내 문단 표시·숨김, 버튼 부제, 녹음 중 비활성, 선택 저장 실패 되돌림을 검증한다. 이 환경에서 확인하지 못한 것은 레이아웃과 색 대비다.

## 확인하지 못한 것

- macOS 14.6+ 동작, 권한 거부 시 동작, 입력 겸용 출력 장치 거부 분기(가정 A1, A2): 개발 PC가 Windows뿐이다.
- 설치한 Windows 앱의 로그인 이후 화면에서 실제 녹음과 전사까지 이어지는 확인: 로그인에 사람 개입이 필요하다.
- 무음 출력 스트림이 다른 앱의 재생 음량을 바꾸지 않는지(가정 A3): 청취 확인이 필요하다.
- 헤드폰 없이 스피커로 재생할 때 마이크가 상대 소리를 다시 녹음하는 문제는 에코 제거가 비목표라 그대로다.
- 녹음 중 기본 출력 장치가 바뀌면(예: 블루투스 헤드폰 연결) cpal이 시스템 트랙 스트림을 무효로 알려 `SYSTEM_AUDIO_DISCONNECTED`로 실패하고, 창은 마이크 트랙까지 포함해 그 녹음을 버린다. 마이크 장치가 끊길 때와 같은 규칙이며 이번에 바꾸지 않았다.
