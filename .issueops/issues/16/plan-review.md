# 계획 검토 기록

## 1차: 수정 요청

- anthropic/claude-opus-5-5 high. 계획의 현재 동작 단언을 코드 줄 번호와 대조했고 Google 토큰 엔드포인트 계약, 오류 매핑, 프런트 시작 순서, Drive 칩, 설정 파일과 기존 Drive 연결의 하위 호환을 공격했으나 설계 결함은 없었다.
- G8 패턴이 signOutOfGateway, sign_out_of_gateway, GatewaySession 같은 흔적을 놓쳐 IPC 명령 4개 제거 기준을 판별하지 못한다.
- 문서 수정과 대체 ADR(성공 기준 4)을 판별하는 게이트가 없다.
- G9가 증거 파일 첫 줄만 확인해 스모크 단계가 실패해도 통과한다.

## 2차: 수정 요청

- anthropic/claude-opus-5-5 high, 2라운드 delta 검토. G8 패턴 확장, 필수 단계 행과 토큰 엔드포인트를 확인하는 G9, 새 ADR이 두 옛 ADR을 가리키는지 보는 G11, tokens_expiring 삭제는 1라운드 지적을 해소했다.
- G10의 명령 수 토큰이 40 frontend 하나뿐이라 AGENTS.md 83행, docs/ARCHITECTURE.md 19·53행, 아키텍처 개요 35행에 옛 명령 수가 남아도 통과한다.
- G10의 auth-gateway 토큰이 ADR 파일 이름에도 걸려 아키텍처 개요의 결정 기록 링크를 지워야만 통과한다. 뒤에 하이픈이 오지 않는 경우로 좁혀야 한다.

## 3차: 통과

- 3라운드는 상향 설정 anthropic/claude-opus-5-5 xhigh(issueops model resolve 결과)로 빈 컨텍스트 omp 세션에서 실행했다.
- 3라운드 delta 리뷰에서 G10의 두 결함이 모두 해소됐다고 판정했다. 범위 문서에서 옛 명령 수(40, 37)와 포트 수(18)가 적힌 아홉 줄은 모두 G10 토큰에 걸리고, 문서 절이 그 아홉 줄을 수정 대상으로 적었다. DESIGN의 `40×40px`처럼 무관한 숫자는 걸리지 않는다. 목표 숫자는 실제 코드와 맞는다. 현재 `tauri.rs`에 명령 40개, `ports.rs`에 trait 18개가 있고, 각각 4개와 2개를 지우면 36과 16이 된다. 수정 후의 36·16 표기는 어느 토큰에도 걸리지 않는다. `auth-gateway([^-]|$)`는 git grep에서 정상으로 컴파일되고, 아키텍처 개요의 ADR 파일 이름을 통과시킨다. 기존 ADR 이름 규칙대로라면 새 ADR 파일 이름도 `auth-gateway-drive`가 되어 결정 기록 링크가 G10을 막지 않는다. README 잔여물 안내 문장도 G10 토큰을 포함하지 않는다. 저자는 명령 수 토큰만으로 검색한 결과를 다섯 줄이라고 적었지만 실제로는 네 줄이었다. 다섯째 줄은 기존 `40 frontend` 토큰이 잡으므로 판정은 바뀌지 않는다.
